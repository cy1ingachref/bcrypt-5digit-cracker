Recover a 5-digit numeric PIN from a bcrypt hash

bcrypt is a one-way hash — there is no decryption. This demo brute-forces the only feasible keyspace for a short numeric secret: every PIN from 00000 to 99999 (100,000 candidates).

How it works

  1. Hash format. A bcrypt hash looks like $2b$04$salt…. The 04 is the cost factor (log2 of the rounds).
  2. Brute force. We try every candidate 00000…99999, running bcrypt.verify(candidate, hash) each time.
  3. Match. The first candidate that verifies is the PIN. Because the space is only 100k, this is tractable — at low cost.

Higher cost = exponentially slower. This is exactly why bcrypt is safe for real passwords: a 12-cost hash of an unconstrained password is effectively uncrackable.

# use all CPU cores

Exit codes: 0 = found, 1 = not found, 2 = bad input / invalid hash.

Ethics & limits

  • bcrypt is not reversible — this is a brute-force search, not decryption.
  • Only feasible because the keyspace is tiny (100k). Don't expect this to break real passwords.
  • Use only on hashes you're authorized to test: your own accounts, CTF challenges you're permitted to solve, or passwords you forgot for your own data.
  • Cracking hashes you don't have permission to attack is illegal.
